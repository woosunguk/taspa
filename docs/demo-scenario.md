# taspa 해커톤 데모 시나리오 (발표 리허설용)

> 목표: **"조직의 신호(캘린더·연차·메뉴)가 매장의 발주 숫자를 바꾸고, 그만큼 잔반이 준다"** 를
> 5분 안에 눈으로 보여준다. 화면 전환은 6번뿐이다.

## 준비 (발표 전 확인)

| 항목 | 확인 방법 |
|---|---|
| 서버(9100) | `curl localhost:9100/actuator/health/liveness` → 200 |
| 웹(3000) | 브라우저에서 `/` 열림 |
| 터널(외부 시연 시) | `https://ridge-acdbentity-meter-pub.trycloudflare.com` |
| Mailpit(가입 시연 시) | `http://localhost:8025` |

**데모 계정 (비밀번호 전부 `1111`)**

| 역할 | 계정 | 착지 화면 |
|---|---|---|
| 직원 | `staff@taspa.example` | `/meal` (식권 QR) |
| 조직관리자 | `orgadmin@taspa.example` | `/console` → 타스파 데모 주식회사 |
| 매장 관리자 | `merchant@taspa.example` | `/merchant` → 본사 구내식당 |
| 플랫폼 관리자 | `admin@taspa.example` | `/admin` |

데모 조직: 타스파 데모 주식회사(직원 42명, 3개월 실적 1,400여 건 시딩).
매장: 본사 구내식당(정액 12,000원, 사업장 연결됨).

## 흐름 (6장면)

### 1. 매장 관리자 — "오늘 몇 인분 준비할까요?" (히어로)
`merchant@taspa.example` 로그인 → 매장 관리.
- 첫 화면이 곧 서비스다: **오늘 준비량**(끼니별) → **예측 vs 실적 추이** → **잔반 절감 효과**.
- 말할 것: "예측이 없던 주방은 품절이 무서워 최대치를 준비합니다. 이 매장은 예측 도입 가정 대비
  **과잉 준비 87% 감소** — 계산 가정까지 화면에 적혀 있습니다(지어낸 숫자가 아닙니다)."

### 2. 신호 설정 — 우측 "빠른 설정" 패널 (차별점 ①)
우상단 **신호 설정** 클릭.
- 신호 7종: 당일 보정 · 재실 인원 · 연차/휴가 · 휴일 · 사내 행사 · 메뉴 · 방법 자동 선택.
- **사내 행사 인지** 토글 → 즉시 저장(감사 로그 기록) → 아래 표가 다시 계산된다.
- 말할 것: "설정은 저장되고, 누가 언제 바꿨는지 감사 로그에 남습니다. 그리고 신호는 매장 총합이
  아니라 **이용 조직별로** 적용됩니다 — A사 휴일이 B사 손님 몫을 깎지 않습니다."

### 3. 기간별 전망 표 — "왜 이 숫자인가" (차별점 ②)
같은 화면 아래 **기간별 예상 식수**.
- 신호 열: 🎪 전사 체육대회(9/4) · 🌴 연차 N명 · 하한 표시.
- 행사일은 근거가 없으면 **"데이터 없음"** — 숫자를 지어내지 않는 것이 신뢰의 근거.
- **이용 조직** 표: 이 매장을 쓰는 조직들과 14일 내 휴일·행사·부재 — 신호가 어디서 오는지.

### 4. 조직관리자 — 신호의 원천 (차별점 ③)
`orgadmin@taspa.example` 로그인 → 조직 관리.
- **캘린더 탭**: 휴일·행사를 **iCalendar 표준**(.ics 업로드/구독)으로 선언 — 자체 입력기가 아니라
  Workspace/Outlook 이 이미 갖고 있는 형식.
- **구성원 탭 → 부재**: 연차·반차(0.5명) 등록 — 12명이 연차인 날 40명분을 만들지 않게.
- 말할 것: "조직이 어차피 관리하는 데이터(달력·연차)가 그대로 매장의 발주 신호가 됩니다.
  이중 입력이 없습니다."

### 5. 직원 + POS — 폐쇄루프 30초

> 단말 세팅 팁: `/pos?key=<등록 키>` 링크로 열면 **입력 없이 자동 등록**됩니다(키는 열리는 즉시
> URL 에서 지워집니다). 단말 여러 대면 이 링크를 QR 로 만들어 찍게 하세요.
- `staff@taspa.example` → 식권 QR 발급 (60초 만료 카운트다운).
- `/pos` (등록된 단말) → 카메라 스캔 → **정액 자동 승인** → 코너 선택(메뉴 귀속).
- 말할 것: "결제 한 건이 곧 실적 한 건 — 예측의 정답 데이터가 스스로 쌓입니다.
  메뉴 코너까지 기록돼 다음 특식일 예측의 근거가 됩니다."

### 6. 마무리 — 정직함이 설계 원칙
- 백테스트 지표(MAPE 11%, WAPE·bias)가 화면에 있고, **틀린 날도 표에 그대로** 있다.
- "데이터 없음"은 0이 아니다 · 부분 합계는 "하한"으로 표시 · 모든 신호는 감사 가능.

## 하지 말 것

- **스위프 중 라이브 시연 금지** (bootRun 클래스가 발밑에서 바뀜 — CLAUDE.md).
- QR 발급은 사용자당 **10초 쿨다운** — 연속 시연 시 직원 계정을 바꿔 가며(emp01~emp40, 전부 1111).
- 데모 중 `ktlintFormat`·서버 재시작 금지(세션 유지 — 재시작하면 전 계정 재로그인).

## 자주 받을 질문에 대한 답

- **"예측 정확도는?"** — 합성 데이터라 수치 자체보다 **구조**를 답한다: 백테스트가 시점 재현
  (미래정보 누수 차단)으로 계산되고, 방법 선택은 홀드아웃 채점으로 검증 가능하다.
- **"실제 결제는?"** — 실 자금이동은 의도적으로 범위 밖. 이중부기 원장 + 3-way 대사까지가 이번 범위.
- **"멀티테넌트 보안은?"** — AWS IAM 스타일 정책 엔진이 유일한 인가 권위. 조직 분해 예측도
  org_id NOT NULL 불변식 위에 서 있다.
