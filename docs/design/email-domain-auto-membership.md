# 이메일 도메인 자동 조직 매칭 — 결정 메모

> 상태: **결정 대기**(구현 안 됨). 야간 자율 세션에서 "가장 큰 온보딩 공백"으로 식별했으나 정책·보안
> 판단이 필요해 자율 범위 밖으로 두었다. 이 문서는 결정을 빠르게 하기 위한 옵션·트레이드오프 정리이며,
> **선택은 하지 않는다**(권고안은 명시).

## 문제

회사 이메일(`alice@acme.com`)로 taspa 에 가입한 개인을, 해당 조직(`acme`)에 자동으로 소속시키고 싶다.
현재는 **초대(invitation)** 만이 유일한 온보딩 경로다(관리자가 이메일로 초대 → 수락 → 멤버십). 자동 매칭이
없으면 대규모 조직 온보딩이 초대 발송에 병목된다.

## 핵심 리스크 (왜 기본값이 곧 결정인가)

**도메인 소유 검증 없이 자동 소속시키면 조직 하이재킹이 가능하다.** 예: 조직 A 가 `gmail.com` 을 자기
도메인으로 등록하면, 모든 gmail 가입자가 A 에 자동 소속된다. 따라서 자동 매칭은 반드시
**(a) 검증된 도메인** + **(b) 공용 이메일 도메인(gmail·naver·outlook 등) 차단** 을 전제해야 한다.
잘못된 기본값은 즉시 보안 사고이므로 승인 없이 구현하지 않았다.

## 결정해야 할 4가지

### D1. 신뢰 도메인의 소스
- **옵션 A — 기존 `sso_domains`(V14) 재사용**: 기업 SSO 커넥션에 이미 검증된 도메인이 있다. 이것으로
  도메인→org(`sso_connection.org_id`) 매핑을 재사용.
  - 장점: 검증 인프라 이미 존재, 추가 마이그레이션 최소.
  - 단점: **SSO 를 설정한 조직만** 자동 매칭 가능. 그리고 "SSO 라우팅용 도메인"과 "비밀번호 가입 자동
    소속용 도메인"은 의미가 다르다 — SSO 를 쓰는 조직이 비밀번호 가입까지 자동 수용하길 원하는가?(→ D3)
- **옵션 B — 신규 `org_domains` 테이블**: 조직별 자동가입 도메인을 독립 관리(+ 검증 플래그·검증 방식).
  - 장점: SSO 와 분리된 명확한 의미, SSO 없는 조직도 사용 가능.
  - 단점: 신규 마이그레이션 + 도메인 검증 플로우(D2) 구현 필요(범위 큼).

### D2. 도메인 소유 검증 방식 (옵션 B 선택 시)
- **DNS TXT 레코드**: 조직이 `_taspa-verify.acme.com` 에 토큰을 게시 → taspa 가 조회해 검증. (표준,
  Google Workspace·Slack 방식.) 구현: DNS 조회 + 검증 상태 저장.
- **관리자 이메일 챌린지**: `admin@acme.com` 등 도메인 대표 주소로 코드 발송(약한 증명).
- **플랫폼 관리자 수동 승인**: 플랫폼 ADMIN 이 도메인 소유를 확인하고 `verified=true` 설정(가장 단순,
  운영 부담 존재).

### D3. SSO 설정 조직에서 비밀번호 가입 자동 소속을 허용할지
- SSO 를 강제하는 조직은 보통 비밀번호 가입 자체를 원치 않을 수 있다. 자동 매칭은 **조직별 opt-in
  플래그**(기본 OFF)로 두어, 관리자가 명시적으로 켤 때만 동작하게 하는 것이 안전.

### D4. 트리거 시점 & 결과
- **트리거**: 이메일 인증 성공 시(도메인 소유 개인 증명 완료 시점). 가입 즉시가 아니라 **검증 후**.
- **결과 역할**: 자동 소속은 `MEMBER` 고정(ORG_ADMIN 자동 부여 금지).
- **중복/충돌**: 이미 멤버면 no-op. 여러 조직이 같은 도메인을 주장하면(검증되었더라도) 충돌 정책 필요
  (선착순 검증 org, 또는 매칭 보류).

## 권고안 (보수적·단계적)

1. **1단계(작게, 안전)**: 옵션 B(신규 `org_domains`) + **D2 = 플랫폼 관리자 수동 승인**(검증 플로우
   자동화는 나중) + **조직별 opt-in 플래그 기본 OFF** + **공용 도메인 하드 차단 리스트** + 트리거는
   이메일 인증 후 + 역할 `MEMBER` 고정. → 오작동해도 기본 OFF·수동 검증이라 하이재킹 불가.
2. **2단계(자동화)**: D2 에 DNS TXT 자가검증 추가(조직 셀프서비스).
3. **SSO 도메인 재사용(옵션 A)은 별도 opt-in** 으로만(SSO≠자동 비밀번호 가입 수용).

이 권고안은 이미 구현된 인프라(초대·멤버십·감사·org 격리·`isOrgAdmin`)를 그대로 재사용하며, 기존
`OrganizationService.ensureJitMembership` 패턴과도 정합한다.

## 미결정이면

자동 매칭 없이도 **초대 기반 온보딩**(완성됨)으로 조직 합류는 가능하다. 자동 매칭은 대규모 온보딩
편의 기능이므로, 결정 전까지 기능 공백은 "치명적"이 아니라 "편의 부재"다.

테스트)을 이어서 진행한다.
