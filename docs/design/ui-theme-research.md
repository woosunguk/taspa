# UI 테마·대시보드 디자인 조사 — 제품 소개 페이지 대응

**출처**: `https://taspa-zerowaste.namo.site/` (제로웨이스트 소개 페이지) + 그 페이지에 실린 화면 목업 5장
(`dashboard` · `predict` · `menu` · `calculate` · `report`).

**목적**: 소개 페이지가 약속하는 화면과 우리 콘솔의 차이를 **항목 단위로** 적어 두고, 그중 무엇이 지금
구현 가능하고 무엇이 데이터가 없어 불가능한지 가른다. 목업은 마케팅 자산이라 **우리에게 없는 기능도
그려져 있다** — 그걸 구분하지 않으면 "화면은 있는데 동작하지 않는" 것을 만들게 된다.

---

## 1. 팔레트·타이포 (적용 완료)

소개 페이지의 CSS 변수를 직접 읽어 가져왔다(눈대중 아님).

| 역할 | 값 | 우리 토큰 |
|---|---|---|
| 브랜드 | `#159253`(green-600) / `#0e7043`(green-700) | `--taspa-brand` |
| 바탕 | `#f3f7ea`(cream) | `--taspa-canvas` |
| 잉크 | `#16301f` · 중립 `#6b7a6f` | `--taspa-ink` / `--taspa-muted` |
| 초록 스케일 | `#eefaf0 → #d6f4dd → #a9e8ba → #4fd07f → #24b866 → #159253 → #0e7043` | `--chart-1..5` |
| 본문 폰트 | Pretendard | `--font-sans` |
| 라운드 | 12 / 20 / 32px | `--radius` (콘솔은 작은 쪽) |
| 그림자 | `rgba(16,48,31,·)` 딥그린 번짐 | `--taspa-shadow-*` |

### 그대로 쓰지 않은 것 (근거 있는 이탈)

1. **브랜드를 green-600 대신 green-700 으로.** `#159253` 위의 흰 글자는 **3.99:1** 로 AA 미달이다.
   소개 페이지는 큰 마케팅 카피라 문제가 없지만 콘솔은 14px 본문 버튼이 대부분이다. `#0e7043` 은
   흰 글자 6.1:1.
2. **다크 값은 소개 페이지에 없어 따로 골랐다.** 처음에 `lime-bright #6ee86a` 를 그대로 썼더니 어두운
   카드 위 대비가 **11:1**(AA 하한의 2.4배)이었고, KPI 숫자와 차트 막대가 전부 그 색이라 **화면이
   눈부셨다**. `#3faa6d`(휘도 0.31, 대비 6:1)로 내렸다. 대비는 "높을수록 좋다"가 아니다 — 어두운
   배경에서 고휘도 채도색을 넓은 면적에 쓰면 잔상이 남는다. 회귀 테스트에 **상한**을 넣었다.

## 2. 목업에서 추출한 디자인 언어 10가지

| # | 패턴 | 목업 위치 | 우리 상태 |
|---|---|---|---|
| 1 | **KPI 5칸 행** — 라벨+ⓘ / 큰 초록 숫자+단위 / 델타 한 줄 | 전 화면 | 부분(3줄 구조는 같고 5칸 정렬·델타 없음) |
| 2 | **KPI 안의 미니 시각화** — 도넛(80%)·스파크라인·미니 영역·미니 막대 | dashboard·calculate·report | ❌ 없음 |
| 3 | **예측 vs 실적 라인차트** — 실선/점선 + 오늘 pill + 값 라벨 | predict | ✅ 구현 완료 |
| 4 | **영역차트(그라데이션 채움)** — 하향 추세 서사 | report(폐기 절감) | ❌ 없음 |
| 5 | **가로 막대 목록** — 이름 + 진행 막대 + 금액 + 상태 pill (표 대신) | dashboard(회사별)·calculate | ❌ 표로 대체 중 |
| 6 | **하단 요약 스트립** — 좌측 초록 액센트 바 + 4칸, `5.3% → 4.1%` 전후 표기 | predict·report | ❌ 없음 |
| 7 | **파이프라인 스테퍼** — 원형 아이콘 + 라벨 + 자동/대기 pill | calculate | ❌ 없음 |
| 8 | **섹션 헤더 우측 액션** — 기간 선택 pill, `자세히 보기`, PDF/다운로드 | 전 화면 | ✅ 있음(Section action) |
| 9 | **델타 표기** — `▲12%` 초록 / `▼` 빨강, 항상 "전월 대비" 같은 기준을 병기 | 전 화면 | ❌ 없음 |
| 10 | **레이아웃 리듬** — KPI 행은 크림 바탕에 **직접**, 그 아래가 카드 | 전 화면 | ❌ 전부 큰 흰 카드 안에 중첩 |

## 3. 만들 수 있는 것 / 만들면 안 되는 것

### 지금 데이터로 가능 (우선순위 순)

1. **KPI 미니 시각화 (#2)** — 도넛은 비율 값(정산 진행률·월 한도 소진율), 스파크라인은 일별 계열이
   이미 있다. `ProgressMeter` 가 이미 비율을 그리므로 그 확장으로 붙는다.
2. **레이아웃 리듬 (#10)** — KPI 행을 Section 밖으로 올리는 구조 변경. 목업과의 체감 차이가 가장 크다.
3. **하단 요약 스트립 (#6)** — 예측·정산 화면에 이미 같은 숫자가 흩어져 있어 모으는 작업이다.
4. **가로 막대 목록 (#5)** — 청구서의 부서별 소계, 정산 명세의 조직별 라인이 정확히 이 형태다.
5. **델타 표기 (#9)** — 전월 대비 값을 서버가 주지 않는 화면이 있어 **기준을 만들 수 있는 곳만**.
   기준 없이 델타를 그리면 숫자를 지어내게 된다.
6. **영역차트 (#4)** — 잔반 절감 추이에 쓸 수 있다. 단 우리 잔반 값은 "가정 위의 계산"이라
   추세선을 그리면 가정이 숫자처럼 보인다 — 캡션을 함께 옮겨야 한다.

### 만들면 안 되는 것 (기능이 없다)

| 목업 요소 | 왜 불가 |
|---|---|
| 메뉴 투표·선호도 (`menu.PNG`, dashboard) | 메뉴 마스터·투표 기능이 **없다**. `consumption_events.menu_ref` 는 전부 NULL |
| 실시간 배식 진행 곡선 | 시간대별 배식 페이스를 적재하지 않는다(D-0 nowcast 미구현) |
| 음식물 폐기량(kg)·CO₂ 환산 | 폐기 계량 입력이 없다. 인분→kg→CO₂ 는 매장 원가·메뉴별 중량이 필요하고 우리에겐 그 데이터가 없다 |
| 조직 변경 자동 반영 건수·업무 시간 절감(시간) | 측정하지 않는 지표다 |
| 평균 만족도 4.6/5 | 만족도 수집 기능이 없다 |
| 파이프라인 스테퍼 (#7) | 자동 정산 파이프라인이 이 형태로 존재하지 않는다(청구서 자동 생성 잡 1개뿐) |

★**화면만 만들고 숫자를 채우지 않는 선택은 없다.** 심사·고객 시연에서 "이 kg 은 어디서 나오나"를
물으면 답이 "지어냈다"가 되고, 그 순간 옆에 있는 **진짜로 검증된 숫자들**(원장·3-way 대사·청구서)까지
같이 의심받는다. 목업의 그 칸들은 비워 두거나 "준비 중"으로 두는 것이 낫다.

## 4. 다크 모드 지침 (이번에 확립)

소개 페이지에는 다크가 없어 우리가 정해야 한다.

1. **다크 값은 라이트의 반전이 아니다.** 밝게 뒤집으면 채도가 그대로 남아 눈부시다.
2. **면적이 클수록 휘도를 낮춘다** — 텍스트 < 막대·영역. 차트 스케일은 브랜드보다 한 단 낮게.
3. **대비에 상한을 둔다.** 하한(AA 4.5)만 보면 11:1 짜리 라임이 통과한다 — 실제로 그렇게 새어
   들어왔다. `data-display.contrast.test.ts` 가 상한 9:1 을 고정한다.
4. 위계는 그림자가 아니라 **표면 밝기**로 만든다(어두운 배경에서 그림자는 읽히지 않는다).
